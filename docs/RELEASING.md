# Releasing

Windows binaries are built by GitHub Actions. Linux is left to distribution maintainers, see
[PACKAGING.md](PACKAGING.md). macOS is not released at the moment.

## Steps

1. Run through the manual hardware checklist in [DEVELOPMENT.md](DEVELOPMENT.md#manual-hardware-checklist).
2. Update `version` in the root `Cargo.toml`, and run `cargo check` to update `Cargo.lock`.
3. Move the entries under `Unreleased` in `CHANGELOG.md` to a new version section.
4. Commit, and push to `main`. Wait for CI to pass.
5. Tag and push:

   ```bash
   git tag -a v0.1.0 -m "v0.1.0"
   ```

   ```bash
   git push origin v0.1.0
   ```

6. The `Release` workflow checks that the tag matches the crate version, runs the tests, and builds
   the ZIP. It then creates a **draft** release with the ZIP and its SHA-256 sum.
7. Download the ZIP from the draft, and try it on a real stick.
8. Publish the draft.

## What is in the ZIP

`usbflash-toolset-<version>-windows-x64.zip`:

- `usbflash-gui.exe`, `usbflash.exe`
- `LICENSE`, `README.md`, `SAFETY.md`
- `THIRD_PARTY_LICENSES.html`, generated by `cargo-about`. Required: the binaries statically
  include the dependencies, whose licenses demand that their notices are distributed along.

The GPL's source requirement is met by the source archives that GitHub attaches to each release.

## Code signing

The builds are unsigned, so SmartScreen warns on first start. To sign them later, for example
through [SignPath](https://signpath.org), which is free for open source projects, add a signing
step in `release.yml` between building and packaging.
